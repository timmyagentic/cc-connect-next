# cc-connect-next v0.3.3-beta.3

## 中文

本次 Beta 交付 macOS 更新后重复权限提示的签名身份修复（[#166](https://github.com/timmyagentic/cc-connect-next/issues/166)、[#167](https://github.com/timmyagentic/cc-connect-next/pull/167)），供实际升级验收。

- macOS Intel 与 Apple Silicon 发布包均采用 Developer ID Application 签名，固定应用标识与开发者 Team，使不同版本保持兼容的代码身份。构建、打包、下载和复用已有发布包时均检查签名与校验和。
- 修复全新 macOS runner 上临时钥匙串缺少完整证书链/搜索范围的问题，编译前先验证有效身份并实际签名探测；退出时恢复原钥匙串列表。Beta.2 在签名阶段停止，未发布 GitHub Release 或 npm 包。
- Agent 会获得实际本地状态目录，并被引导先查能力清单和相关目录，减少无关的全用户目录搜索及由此触发的隐私权限请求。
- 保留 Beta.1 的 Prompt 定时任务独立模型配置和既有任务兼容性；详见 [Beta.1 发行说明](https://github.com/timmyagentic/cc-connect-next/releases/tag/v0.3.3-beta.1)。

从旧的 ad hoc 签名版本首次升级，macOS 可能仍要求重新授权一次。真实升级后的权限延续、首次身份迁移、公证与 Gatekeeper 验收尚未完成；Developer ID 签名本身不代表这些验收已通过。迁移与排查步骤见 [macOS 签名说明](https://github.com/timmyagentic/cc-connect-next/blob/v0.3.3-beta.3/docs/macos-signing.md)。

```sh
npm install -g cc-connect-next@beta
cc-connect-next --version
```

也可使用 `cc-connect-next update beta`。GitHub Latest 和 npm `latest` 保持稳定版 v0.3.2。发布不会自动升级或重启运行中的服务。

## English

This beta delivers the macOS signing-identity fix for repeated permission prompts after updates ([#166](https://github.com/timmyagentic/cc-connect-next/issues/166), [#167](https://github.com/timmyagentic/cc-connect-next/pull/167)) for real upgrade acceptance testing.

- Both Intel and Apple Silicon macOS archives use Developer ID Application signing with a stable application identifier and developer team, preserving compatible code identity across versions. Build, packaging, download and release-reuse checks reject missing or incompatible signatures and invalid checksums.
- Fix isolated signing on fresh macOS runners by preparing the certificate chain and search list, resolving a valid identity and signing a probe before compilation. Restore the original search list on exit. Beta.2 stopped at signing and was not published to GitHub Releases or npm.
- Connected Agents receive the effective local state directory and guidance to inspect capabilities and relevant directories first, reducing unnecessary searches across unrelated protected user directories.
- Includes Beta.1's independent models for prompt-based scheduled jobs and existing-job compatibility. See the [Beta.1 release notes](https://github.com/timmyagentic/cc-connect-next/releases/tag/v0.3.3-beta.1).

The first migration from an older ad hoc signature may still require a new macOS authorization. Real upgrade permission persistence, initial identity migration, notarization and Gatekeeper acceptance remain unverified; Developer ID signing alone does not establish those outcomes. See the [macOS signing guide](https://github.com/timmyagentic/cc-connect-next/blob/v0.3.3-beta.3/docs/macos-signing.md) for migration and diagnosis.

Install with `npm install -g cc-connect-next@beta` or `cc-connect-next update beta`. GitHub Latest and npm `latest` remain on stable v0.3.2. Publication does not upgrade or restart running services.
