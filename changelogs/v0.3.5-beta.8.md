# cc-connect-next v0.3.5-beta.8

## 中文

- 修复开启群聊补读后忙时消息始终排队的问题，恢复 `busy_message_mode = "steer"` 的追加能力。
- 已有补读回执时，同人追加直接进入当前回合；首次、跨人或身份未知时，先按现有预算补读，再将背景与当前请求一起 steer。
- 当前与历史图片、文件一起送达并保留归属；profile、model、reasoning 与群绑定继续保持独立回合约束。
- 补读回执仅在 steer 明确接受且回合成功完成后提交，覆盖回合完成先于 RPC 返回的情况；拒绝或结果未知时保留背景供后续重试。
- 自动化回归、并发与群聊用户流程验证通过。真实飞书多人交替 @、停止/撤回、媒体及真实模型交付仍待验证。
- Beta 安装：`npm install -g cc-connect-next@beta`。稳定渠道保持 v0.3.4。

## English

- Restore busy-message steering when group conversation catch-up is enabled.
- With existing catch-up receipts, same-sender follow-ups steer directly. First use, a different sender or unknown identity triggers the existing bounded read before background and the current request are steered together.
- Preserve current and historical images, files and attribution. Profile, model, reasoning and group bindings retain separate-turn boundaries.
- Commit catch-up receipts only after definite steer acceptance and successful turn completion, including completion before the RPC response. Rejected or uncertain input leaves background retryable.
- Automated regression, concurrency and group conversation journey checks passed. Live Feishu multi-user mentions, stop/recall, media and real model delivery remain unverified.
- Install with `npm install -g cc-connect-next@beta`. Stable channels remain on v0.3.4.
