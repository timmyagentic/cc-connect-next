# cc-connect-next v0.3.1

## 中文

本稳定版汇总 v0.3.1 beta1–3 的媒体输入、回合可靠性、会话速度、群聊上下文和反馈改进。

- 修复 Agent 错误及提示发送失败与会话清理重叠时的并发读写；统一受锁会话快照，保留存活会话和队列处理语义，并补充并发回归测试。
- 提供无密钥云开发 bootstrap 与精确提交验证入口，固定工具链并隔离工作区缓存。
- 修复飞书图片、视频、文件静默遗漏：兼容首次 Range 探测缺少 Content-Range 的响应，保留后续分块的严格校验；传递内嵌视频文件与可用封面，校验 MIME，明确报告下载、元数据及 Agent 落盘失败，并隔离同名附件。
- 改善 Codex EOF、读取失败及满队列时的终态处理；提供登录恢复指引，保留失败回合的续接 ID；支持显式 CLI 路径和 macOS 内置 CLI 发现。
- `/speed` 支持为后续回合保存当前会话的受支持速度档位，保留模型、推理强度和历史。
- 飞书/Lark 普通群聊默认共享会话，真实话题默认隔离；可按配置在明确提及时补充有界近期讨论。保留历史及显式 opt-out，不新增轮询或扩大读取权限。
- Foundation Feedback v2 保存有界脱敏回合诊断、原始请求、报告 ID 和回执，减少重试重复提交；认证和额度错误不自动建议缺陷反馈，手动反馈保留。
- 统一飞书卡片操作者权限校验；保留当前与已获准引用附件。Claude 用户提问仍可交互，拒稿不会拼入答案，进程关闭与输入写入有界处理。
- 修复 idle reset 锁、工作区不兼容会话 ID、launchd 原域重启和 Cron 时区显示；去除会话 token/context 采集，账户 `/usage` 保留。升级版本探测不再触发 daemon 日志初始化。

### 升级与兼容

```sh
npm install -g cc-connect-next@latest
cc-connect-next --version
```

也可使用 `cc-connect-next update` 或聊天 `/upgrade`。正式发布后 Stable/npm latest 为 0.3.1；安装与加载正在运行的服务分别进行，发布本身不会重启服务。

自托管 Relay 须先具备 v1/v2 双协议及 FEEDBACK_REPORTS SQLite 迁移。旧 `/v1/feedback` 配置映射至同源 v2；协议拒绝不会降级重发。群聊默认值变化不会搬移或合并旧历史，需旧行为时显式配置。

引用附件仍要求明确 @机器人及当前用户为原上传者。没有新增必填配置或飞书权限。历史 QA 的机器人样例解析/下载和一次真实 Codex 媒体读取属于组件证据；真人入站、本人引用接受/拒绝边界、语音转写及原生 Windows 执行仍为 UNVERIFIED。视频文件/封面可用不代表模型理解整段视频。缺少 Content-Range 的现场异常由本地回归覆盖，未现场复现。

## English

This stable release collects the v0.3.1 beta1–3 improvements to media delivery, turn reliability, session speed, group context and feedback.

- Synchronize session snapshots when Agent errors or prompt-send failures overlap cleanup, retaining live-session and queue behavior with concurrent regression coverage.
- Add secret-free cloud bootstrap and exact-commit validation with a pinned toolchain and workspace-local caches.
- Deliver Feishu images, embedded/standalone video and files reliably. Handle an initial Range probe missing Content-Range while retaining strict subsequent validation, MIME checks, cancellation, explicit failures and per-source filename isolation.
- Finish Codex turns on EOF/read failure, retain terminal events under backpressure, preserve late session IDs and provide actionable authentication recovery. Honor explicit CLI paths and discover bundled macOS CLIs.
- Persist supported `/speed` choices for subsequent turns without changing model, effort or history.
- Share ordinary Feishu/Lark group sessions and isolate real topics by default. Optional bounded context on explicit mentions retains attribution and deduplication; no new polling or broader permissions.
- Foundation Feedback v2 preserves bounded redacted diagnostics, initiating requests, report IDs and receipts. Authentication/quota errors keep manual feedback without automatic bug-report offers.
- Enforce card callback admission; retain approved quoted files alongside current attachments. Keep Claude questions interactive, discard rejected drafts and bound process shutdown/blocked writes.
- Fix idle-reset locking, incompatible workspace IDs, launchd restart domains and cron timezone display. Remove session token/context telemetry while preserving account `/usage`; make version probing independent of daemon logging.

Install with `npm install -g cc-connect-next@latest`, `cc-connect-next update` or chat `/upgrade`. Installing and loading a running service are separate steps. Self-hosted Relay deployments require dual v1/v2 support and the FEEDBACK_REPORTS migration first. Existing history is retained, not merged into new shared/topic sessions; explicit opt-outs remain available.

Quoted attachments retain explicit-mention/original-uploader restrictions. No additional required configuration or Feishu permissions. Previous bot-generated fixture and real Codex media checks are component evidence: human-inbound end-to-end, own-upload quote boundaries, speech transcription and native Windows execution remain UNVERIFIED. Video file availability does not establish full-video model understanding.
