# cc-connect-next v0.3.3-beta.1

## 中文

本次 Beta 新增 Prompt 定时任务独立模型配置（[#165](https://github.com/timmyagentic/cc-connect-next/pull/165)），首先支持 Codex 的 `exec` 和 `app_server` 后端。

- `cron add --prompt ... --model <id>` 为任务指定模型；`cron edit <id> model ""` 恢复继承。CLI、API 和 Web Cron 页面使用同一配置，未设置模型的旧任务保持原有继承行为。
- 任务模型仅作用于该任务轮次，不修改 Project/Agent 默认模型或 Provider。复用会话、忙时队列、并发任务及会话重启后，普通聊天仍使用其默认模型。
- 覆盖前确认具体默认模型可以恢复；不支持的 Agent、Shell 任务模型或无法确认默认模型的覆盖会明确失败，不静默切换模型。静默任务也保存失败、取消和超时记录。
- 同时包含 main 已合并的产品网站视觉更新（[#164](https://github.com/timmyagentic/cc-connect-next/pull/164)）。

```sh
npm install -g cc-connect-next@beta
cc-connect-next --version
```

也可使用 `cc-connect-next update beta`。GitHub Latest 和 npm `latest` 保持稳定版 v0.3.2。发布不会自动升级或重启运行中的服务。

## English

This beta adds independent models for prompt-based scheduled jobs ([#165](https://github.com/timmyagentic/cc-connect-next/pull/165)), initially supporting both Codex `exec` and `app_server` backends.

- Select a job model with `cron add --prompt ... --model <id>`; clear it with `cron edit <id> model ""` to inherit again. CLI, API and Web Cron settings agree; existing jobs without a model keep their inheritance behavior.
- Overrides are scoped to the job turn and do not change Project/Agent defaults or providers. Ordinary chat restores its default across reused sessions, busy queues, concurrent jobs and session restarts.
- A concrete default must be restorable before accepting an override. Unsupported Agents, shell-job models and unresolved defaults fail explicitly without selecting a replacement model. Muted jobs also retain failure, cancellation and timeout records.
- Includes the product website visual update already merged into main ([#164](https://github.com/timmyagentic/cc-connect-next/pull/164)).

Install with `npm install -g cc-connect-next@beta` or `cc-connect-next update beta`. GitHub Latest and npm `latest` remain on stable v0.3.2. Publication does not upgrade or restart running services.
