# cc-connect-next v0.3.5-beta.9

## 中文

- 群聊首次补读近期背景，之后从上次已交付的位置读取新增讨论；普通输入、排队和 steer 使用一致规则。
- macOS 本地 Codex 默认使用原生权限配置，限制访问与工作区无关的个人目录，降低意外触发隐私授权弹窗的风险。需要稳定版 Codex CLI 0.163.0 或更新版本；可通过 `[macos_privacy] enabled = false` 恢复原有权限选择。
- 工作区所在的个人目录类别保留原模式权限；此功能不是单项目隔离。远程 Agent、其他 Agent 和独立 shell 不在保护范围内。
- 自动化、并发和合成目录沙箱验证通过；真实飞书多人交互及干净 macOS 账户上签名 launchd 版本的弹窗验收尚未验证。
- Beta 安装：`npm install -g cc-connect-next@beta`。稳定渠道保持 v0.3.4。

## English

- Read recent group context initially, then fetch only discussion added since the last delivered input, consistently across normal, queued and steered messages.
- Local Codex on macOS now uses a native permissions profile to restrict unrelated personal directories and reduce unintended privacy prompts. Stable Codex CLI 0.163.0 or later is required; `[macos_privacy] enabled = false` restores the previous permission selection.
- The personal-directory category containing the workspace retains its original mode permissions; this is not per-project isolation. Remote agents, other agents and standalone shells are outside the protection scope.
- Automated, race and synthetic sandbox tests passed. Live multi-user Feishu interactions and signed launchd privacy-prompt acceptance on a clean macOS account remain unverified.
- Install with `npm install -g cc-connect-next@beta`. Stable channels remain on v0.3.4.
