# cc-connect-next v0.3.6-beta.13

## 中文

- 会话签名恢复以 [PR #237](https://github.com/timmyagentic/cc-connect-next/pull/237) 为准：本地 Codex app-server 遇到明确的加密上下文校验错误并确认回合失败后，停止专用进程、清理原历史中的加密状态，再在**同一原生会话中静默重试一次**。不创建替代会话、不导入到新线程，也不发送恢复进度提示。这取代 [PR #234](https://github.com/timmyagentic/cc-connect-next/pull/234) 的新线程恢复方式。
- 保留普通文本、工具调用和已记录结果、聊天绑定、待处理消息顺序及模型设置。清理前先保存权限为 0600 的原始历史副本；备份失败不覆盖原文件。仅存在于密文中的上下文不会参与重试，备份保留供人工恢复，不自动注入。保留工具记录不构成后续模型操作绝不重复的保证。
- 隔离进程重启前后的审批请求，避免旧审批结果进入新进程；启用普通聊天重启检查点时，在重试前持久化新提交身份及一次重试预算。历史无法解析或记录未完整写入、身份不匹配、后台命令仍运行等无法安全核对的情况停止恢复。`/stop` 可取消。
- 新增 [PR #235](https://github.com/timmyagentic/cc-connect-next/pull/235) 的普通聊天重启恢复，仅适用于本地 Codex app-server、飞书 rich Card 2.0 和持久会话存储组合。服务恢复后先核对原生记录：已完成回合仅补交付答案，被中断回合沿原会话续跑；保持待处理输入顺序，并在远端更新前保存卡片序号。Cron、Timer、Heartbeat、Shell 及其他后端不在此范围。
- 验证边界：测试使用隔离历史文件、模拟 app-server 和平台回归；未对真实上游签名故障、真实飞书群或运行中 daemon 升级作端到端验收，也未清理任何真实用户会话历史。
- 安装：`npm install -g cc-connect-next@beta`。稳定渠道保持 v0.3.5。

## English

- Signature recovery follows [PR #237](https://github.com/timmyagentic/cc-connect-next/pull/237): after an explicit encrypted-context validation error and a confirmed failed turn, the local Codex app-server adapter stops its dedicated process, clears encrypted state from the original history, and **silently retries once in the same native thread**. It creates no replacement thread, imports no history into another thread, and sends no recovery-progress message. This supersedes the replacement-thread design from [PR #234](https://github.com/timmyagentic/cc-connect-next/pull/234).
- Preserve ordinary text, tool calls and recorded results, chat bindings, queued-input order, and model settings. Before rewriting history, save an exact original copy with mode 0600; failure to save it leaves the original untouched. Encrypted-only context is not available to the retry. The backup remains for manual recovery and is not injected automatically. Preserved tool receipts do not guarantee that a model can never repeat a later action.
- Isolate approval requests across process restarts so old responses cannot reach the new process. When ordinary-chat restart checkpoints are active, persist the new submission identity and single-retry budget before continuing. Unparseable or partially written history, mismatched identities, active background commands, or other unreconciled state stop recovery. `/stop` cancels it.
- Add [PR #235](https://github.com/timmyagentic/cc-connect-next/pull/235) ordinary-chat restart recovery for the combination of local Codex app-server, Feishu rich Card 2.0, and persistent session storage. Reconcile native history first: completed turns only redeliver the recorded answer, while interrupted turns continue in the existing conversation. Preserve queued-input order and save card sequence numbers before remote updates. Cron, Timer, Heartbeat, Shell, and other backends remain outside this path.
- Verification boundaries: tests use isolated history fixtures, a simulated app-server, and platform regressions. Live upstream signature failures, live Feishu groups, and running daemon upgrades were not exercised end to end. No real user session history was cleaned.
- Install with `npm install -g cc-connect-next@beta`. Stable remains v0.3.5.
