# cc-connect-next v0.3.6-beta.13

## 中文

- 本地 Codex app-server 遇到明确的加密上下文校验错误时，每个用户回合可尝试一次自动恢复：确认原生回合失败后，导入可完整读取的历史与已完成工具的记录结果，在新会话绑定保存成功后继续未完成的请求。旧会话保留，恢复期间沿用聊天、待处理消息队列和回复卡片。详见 [PR #234](https://github.com/timmyagentic/cc-connect-next/pull/234)。
- 历史不完整、必要历史仅存在于不可读加密内容中、工具结果不明、后台命令仍运行或已接受的 steer 输入尚无法核对时，停止恢复并报告原错误。导入历史本身不重新执行工具；这不构成模型后续操作绝不重复的保证。`/stop` 可取消恢复。
- 依赖 app-server 的 `thread/read`、`thread/backgroundTerminals/list` 和 `thread/inject_items` 接口。不支持这些接口的版本继续报告原失败。
- 未对真实上游签名故障、真实飞书群或运行中 daemon 升级作端到端验收。
- 安装：`npm install -g cc-connect-next@beta`。稳定渠道保持 v0.3.5。

## English

- The local Codex app-server adapter can attempt one recovery per user turn after an explicit encrypted-context validation failure. Once the native turn has definitively failed, it imports complete readable history and recorded results of completed tools, persists the replacement session binding, and continues the unfinished request. The original thread remains in history while the chat, queued messages, and reply card are retained. See [PR #234](https://github.com/timmyagentic/cc-connect-next/pull/234).
- Recovery stops with the original error if history is incomplete, required history exists only in unreadable encrypted content, tool outcomes are unknown, background commands remain active, or accepted steer input cannot be verified. Importing history does not itself execute tools again; this does not guarantee that a model can never repeat a later action. `/stop` cancels recovery.
- Requires app-server support for `thread/read`, `thread/backgroundTerminals/list`, and `thread/inject_items`. Unsupported versions keep the original failure behavior.
- Live upstream signature failures, live Feishu groups, and running daemon upgrades were not exercised end to end.
- Install with `npm install -g cc-connect-next@beta`. Stable remains v0.3.5.
