# cc-connect-next v0.3.6-beta.8

## 中文

本版本包含原 beta.7 准备的变更。beta.7 在 CI 校验发现 lint 问题后停止，未发布 GitHub Release 或 npm 包。

- Cron / Timer 执行历史现在可以通过 `[history] enabled = true` 显式开启，默认关闭。开启后在 `data_dir/history.sqlite` 中保存任务版本、独立运行记录、调度与执行结果及会话关联；现有 JSON 调度方式保持不变。关闭时不打开、恢复或写入历史库，已有数据保留。修改配置后需重启。详见 [PR #223](https://github.com/timmyagentic/cc-connect-next/pull/223)。
- 修复飞书启用 `group_context` 时遗漏显式引用及首次参与话题原帖的问题。旧图片、机器人原帖和已读游标之前的引用继续进入现有受控上下文流程，并保留真实时间、去重、预算及群／话题范围校验；普通追加消息不重放旧背景。详见 [PR #224](https://github.com/timmyagentic/cc-connect-next/pull/224)。
- 飞书 / Lark 新增可选 `message.observed` Hook，同步交付真人提及的路由元数据，不包含消息正文或显示名称。观察先于 Agent 去重、启动时间及机器人回复过滤，仍遵守发送人、群范围和仅群聊限制；消费者失败会回传 SDK。消费者须按原消息 ID 幂等处理，覆盖仍受应用成员关系、权限及订阅限制，不提供历史轮询或无限重投保证。详见 [PR #226](https://github.com/timmyagentic/cc-connect-next/pull/226)。
- 修正 Hook、任务历史资源清理及群上下文代码中的 lint 问题，不改变原有业务行为。
- 本次发布未在真实飞书群中或运行中的 daemon 升级流程中再次验收。
- 安装：`npm install -g cc-connect-next@beta`。稳定渠道保持 v0.3.5。

## English

This release includes the changes prepared for beta.7. That release was stopped after CI detected lint issues; no beta.7 GitHub Release or npm package was published.

- Opt in to Cron / Timer execution history with `[history] enabled = true`; it is disabled by default. When enabled, `data_dir/history.sqlite` records job versions, independent runs, scheduler and execution results, and session links while existing JSON scheduling remains unchanged. Disabling history leaves existing data intact without opening, recovering, or writing the database. Restart after configuration changes. See [PR #223](https://github.com/timmyagentic/cc-connect-next/pull/223).
- Fix missing explicit replies and initial topic roots when Feishu `group_context` is enabled. Old images, bot-authored originals, and references older than the read cursor use the existing controlled context pipeline with original timestamps, deduplication, budgets, and chat/topic scope checks. Ordinary follow-up messages do not replay old background. See [PR #224](https://github.com/timmyagentic/cc-connect-next/pull/224).
- Add an opt-in Feishu / Lark `message.observed` Hook that synchronously delivers human-mention routing metadata without message bodies or display names. Observation precedes Agent deduplication, startup-time filtering, and bot-reply gates while retaining sender, chat-scope, and group-only restrictions; consumer failures propagate to the SDK. Consumers must be idempotent by original message ID. Coverage still depends on app membership, permissions, and subscriptions; there is no history polling or unlimited-redelivery guarantee. See [PR #226](https://github.com/timmyagentic/cc-connect-next/pull/226).
- Resolve lint findings in Hook execution, scheduled-history resource cleanup, and group-context code without changing business behavior.
- Live Feishu groups and running daemon upgrades were not exercised again for this release.
- Install with `npm install -g cc-connect-next@beta`. Stable remains v0.3.5.
