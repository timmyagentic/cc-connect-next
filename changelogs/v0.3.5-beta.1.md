# cc-connect-next v0.3.5-beta.1

## 中文

### 更新亮点

- Prompt 定时任务可单独设置推理强度，也可与模型分别配置；支持 CLI、API 和 Web，清空后恢复继承默认值。
- 聊天更新在同一张飞书卡片上展示确认、等待任务完成、安装校验和重启后的结果，减少重复消息。
- 更新等待所有项目已接收的任务结束，阻止安装期间重复更新或竞争重启；失败结果保留，可通过 `/upgrade status` 查询。

### 升级注意

- 本版为 Beta，基于 v0.3.4，包含此前的 systemd 首次安装修复。GitHub Latest 与 npm `latest` 保持 v0.3.4；npm `beta` 更新到本版。
- 定时任务推理强度目前由 Codex exec/app_server 支持；具体模型和 Provider 是否接受所选强度仍由上游决定。旧任务未设置此字段时保持继承。
- macOS 真实升级后的权限延续、签名迁移、公证与 Gatekeeper 验收，以及物理手机布局和屏幕阅读器行为仍为 UNVERIFIED。参见 [签名说明](https://github.com/timmyagentic/cc-connect-next/blob/v0.3.5-beta.1/docs/macos-signing.md)。

```sh
npm install -g cc-connect-next@beta
cc-connect-next --version
```

## English

### Highlights

- Set reasoning effort independently for prompt-based scheduled jobs through the CLI, API, and Web UI. Clear the override to inherit defaults.
- Review updates, wait for active work, follow installation verification, and recover the result after restart on the same Feishu card.
- Updates wait for accepted tasks across projects, prevent competing installations and restarts, and retain results for `/upgrade status`.

### Upgrade notes

- This beta builds on v0.3.4 and retains its systemd first-install fix. GitHub Latest and npm `latest` remain at v0.3.4; npm `beta` advances to this release.
- Per-job reasoning effort currently supports Codex exec/app_server. Model/provider acceptance remains upstream-dependent. Existing jobs without an override continue inheriting defaults.
- Real macOS upgrade permission continuity, signing migration, notarization and Gatekeeper acceptance, physical phone layout, and screen-reader behavior remain UNVERIFIED. See the [signing guide](https://github.com/timmyagentic/cc-connect-next/blob/v0.3.5-beta.1/docs/macos-signing.md).

Install with `npm install -g cc-connect-next@beta` or `cc-connect-next update beta`.
