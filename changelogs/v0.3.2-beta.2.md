# cc-connect-next v0.3.2-beta.2

## 中文

合并 PR #154 和 PR #155：机器人即时私聊完成通知，以及飞书/Lark 本地图集发送。

- 任务成功并送达最终答复后，由**同一个机器人**向明确配置的当前回合发起人立即私聊一次，附简要摘要和原对话链接。不在原话题追加短通知，不查询已读，也不再安排延迟提醒。默认关闭，按机器人应用分别配置 `completion_notify` 和 `completion_notify_users`。旧 `unread_reminder` 开关及收件人字段继续作为兼容别名；旧 `unread_reminder_delay_mins` 不再延迟发送，历史待提醒记录不会补发。
- 通过一次 `cc-connect-next send` 中的重复 `--image` 批量发送本地图片时，飞书/Lark 默认将两张及以上图片按输入顺序组织成双列 Card 2.0 图集，每条消息最多 5 张原图；十张图片会拆成两条图集消息。单张仍发为原生图片消息；关闭 `enable_feishu_card` 时继续逐张发送。不合成或裁剪原图。
- 图集先上传整批图片，再发一条卡片；某张上传失败时不会发送残缺图集。传输重试复用本批 UUID，不会重发此前已确认的批次。最终失败会报告已确认发送数量并停止后续内容；再次执行属于新投递，请先核实失败批次，避免重复。

升级 Beta：

```sh
npm install -g cc-connect-next@beta
cc-connect-next --version
```

Stable 与 npm `latest` 仍为 v0.3.1。本次不自动启用完成通知、不重启运行中的服务；新通知配置及链接边界见[说明](https://github.com/timmyagentic/cc-connect-next/blob/v0.3.2-beta.2/docs/completion-notifications.md)。

本地测试覆盖指定用户、同一机器人私聊、原对话链接、失败/静默/取消边界、并发和重启去重，以及图集顺序、原图完整性、双列结构、上传失败、重试 UUID、话题与分批路由。真实飞书/Lark 私聊投递和客户端跳转仍为 **UNVERIFIED**；非 macOS ARM 二进制未现场运行。

## English

Merge PR #154 and PR #155: immediate bot-private completion notifications and native Feishu/Lark image galleries.

- After a successful final answer is delivered, the same bot immediately sends one private notice to the explicitly configured owner of that turn, with a short summary and a link to the original conversation. No extra topic notice, read-status query, or delayed reminder. Disabled by default; configure `completion_notify` and `completion_notify_users` per bot app. The old unread-reminder enable/recipient keys remain aliases, the old delay is ignored, and historical pending records are never replayed.
- Repeating `--image` in one `cc-connect-next send` call groups two or more local images into ordered, two-column Card 2.0 galleries with up to five originals per message. Ten images produce two galleries. A single image remains a native image message; disabling `enable_feishu_card` retains individual sends. Originals are not composited or cropped.
- Upload a full image group before publishing its card, so a failed upload cannot produce a partial gallery. Transient retries reuse that group's UUID and do not replay earlier confirmed groups. A final failure reports the confirmed count and stops later content; a new CLI invocation is a new delivery, so inspect the failed group before retrying.

Install or update with `npm install -g cc-connect-next@beta`. GitHub Latest and npm `latest` remain on stable v0.3.1. Publication does not enable completion notices or restart a running service. Real Feishu/Lark private delivery/client navigation remain **UNVERIFIED**; non-macOS ARM binaries were not executed locally.
