## 中文

修复 Linux 首次安装后台服务失败的问题：`WorkingDirectory` 现在按 systemd 的目录路径规则生成，不再套用 `ExecStart` 参数引号。普通目录、带空格、百分号、引号、反斜杠和中文的目录均经过真实 systemd 解析、启动及进程工作目录验证。无法安全表示的换行、NUL 和尾部空白会在改写现有服务文件前明确报错。

- 发布验证新增真实 systemd 门禁；服务管理器缺失或无法启动时直接失败，不能以跳过测试代替通过。
- README 提供可交给编码 Agent 执行的首次安装 Prompt，覆盖配置、飞书扫码、前台消息和后台服务验收。
- 包含此前 Beta 的 Prompt 定时任务独立模型配置、产品网站更新和 macOS Developer ID 签名修复。详情见 [Beta.1](https://github.com/timmyagentic/cc-connect-next/releases/tag/v0.3.3-beta.1) 和 [Beta.3](https://github.com/timmyagentic/cc-connect-next/releases/tag/v0.3.3-beta.3)。macOS 真实升级后的权限延续、公证与 Gatekeeper 验收仍未完成，详见 [签名说明](https://github.com/timmyagentic/cc-connect-next/blob/v0.3.3/docs/macos-signing.md)。

```sh
npm install -g cc-connect-next@latest
cc-connect-next --version
```

GitHub Latest 和 npm `latest` 更新为 v0.3.3。发布本身不会升级或重启正在运行的实例。

## English

Fix Linux daemon installation failing on first setup. `WorkingDirectory` now uses systemd's literal directory-path syntax instead of `ExecStart` argument quoting. Real systemd validation checks parsing, service startup and the process's actual working directory for plain paths, spaces, percent signs, quotes, backslashes and Unicode. Line breaks, NUL and trailing whitespace are rejected before changing an existing service file.

- Release validation now requires real systemd checks. An unavailable service manager or failed startup fails the gate rather than skipping acceptance.
- The README includes a first-install prompt for coding agents, covering configuration, Feishu setup, foreground messages and daemon acceptance.
- Includes the preceding betas' independent models for prompt-based scheduled jobs, website updates and macOS Developer ID signing fixes. See [Beta.1](https://github.com/timmyagentic/cc-connect-next/releases/tag/v0.3.3-beta.1) and [Beta.3](https://github.com/timmyagentic/cc-connect-next/releases/tag/v0.3.3-beta.3). Real macOS upgrade permission persistence, notarization and Gatekeeper acceptance remain unverified; see the [signing guide](https://github.com/timmyagentic/cc-connect-next/blob/v0.3.3/docs/macos-signing.md).

Install with `npm install -g cc-connect-next@latest` or `cc-connect-next update stable`. GitHub Latest and npm `latest` advance to v0.3.3. Publication alone does not upgrade or restart running instances.
