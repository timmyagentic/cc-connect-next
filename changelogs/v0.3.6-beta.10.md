# cc-connect-next v0.3.6-beta.10

## 中文

- 新增 `reply.completed` Hook：飞书群聊富卡片模式最终答复成功送达后，提供原请求 `source_id`、最终答复 `answer_id`、群 `chat_id` 和完成时间 `completed_at_ms`。发生替换补发时使用实际送达的消息 ID；事件仅携带路由元数据，不包含答复正文。详见 [PR #230](https://github.com/timmyagentic/cc-connect-next/pull/230)。
- 私聊、静默答复、最终投递失败或缺少完整路由 ID 时不触发。继续使用现有 Hook 配置和同步／异步分发规则；这是 best-effort 通知，不承诺持久投递或失败重投。
- 未重新验收真实飞书群或运行中的 daemon 升级。此前 beta.9 的 npm 安装退出修复保持不变。
- 安装：`npm install -g cc-connect-next@beta`。稳定渠道保持 v0.3.5。

## English

- Add a `reply.completed` Hook after a Feishu group rich-mode final reply is successfully delivered. It provides the original request `source_id`, delivered answer `answer_id`, group `chat_id`, and `completed_at_ms`. Replacement sends report the actual delivered message ID. Events contain routing metadata, not reply content. See [PR #230](https://github.com/timmyagentic/cc-connect-next/pull/230).
- Private chats, silent replies, failed final delivery, and incomplete routing IDs do not emit this event. Existing Hook configuration and synchronous/asynchronous dispatch rules still apply; delivery is best-effort, without durable-delivery or retry guarantees.
- Live Feishu groups and running daemon upgrades were not exercised again. The npm installer exit fix from beta.9 is unchanged.
- Install with `npm install -g cc-connect-next@beta`. Stable remains v0.3.5.
