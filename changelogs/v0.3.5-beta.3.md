# cc-connect-next v0.3.5-beta.3

## 中文

### 更新亮点

- 飞书和 Lark 支持按群固定模型：使用 `/model group <name>` 设置、`/model group` 查看、`/model group reset` 恢复默认。设置覆盖同群全部成员和新旧话题，跨新建会话及服务重启保留；其他群继续按各自设置或默认模型运行。
- 群模型在新请求执行时解析，包括排队请求；显式单次模型优先，不打断正在生成的回复。遇到后端或 Provider 不匹配时明确报错，避免静默切换模型。
- 修复启用 Bridge 但尚未连接外部适配器时的整体健康误报：Bridge 首次待连接显示为 `standby`，同项目已就绪的飞书等平台可正常通过健康检查和升级恢复判定。
- Bridge-only 项目在首个适配器连接前仍未就绪；最后一个已连接适配器断开、监听失败及其他平台故障仍报告异常。启动告警只点名受影响的平台。

### 使用与验证边界

- 群固定模型目前由飞书/Lark提供已验证群身份，并要求后端支持逐回合模型（Codex `exec` 和 `app_server`）。使用当前 Provider 可选模型，不切换 Provider；`/model switch` 继续修改项目或工作区默认值。
- 本地构建、完整单元测试、关键用户流程和 Bridge 健康回归通过。真实飞书消息及付费模型调用未在本轮重新验证。
- 本版为 Beta；npm `beta` 更新至本版，稳定渠道继续保持 v0.3.4。

```sh
npm install -g cc-connect-next@beta
cc-connect-next --version
```

已有安装也可执行 `cc-connect-next update beta`。

## English

### Highlights

- Pin a model for a verified Feishu/Lark group with `/model group <name>`, inspect it with `/model group`, and restore default inheritance with `/model group reset`. The setting covers all members and existing/new topics and survives new sessions and restarts.
- Resolve group models when each request executes, including queued requests. Explicit one-shot selections take precedence without interrupting an active reply. Backend or Provider mismatches fail explicitly instead of silently changing models.
- Fix false overall-unhealthy reports when Bridge is enabled but has not connected its first adapter. Initial Bridge `standby` no longer blocks healthy native platforms in the same project, including post-update connection receipts.
- A Bridge-only project stays unready until an adapter connects. Losing the last connected adapter, listener failures and other platform failures still report unavailable; startup warnings name only affected platforms.

### Usage and verification boundaries

- Group pinning requires verified group identity from Feishu/Lark and per-turn model support (Codex `exec` and `app_server`). It uses models from the current Provider without changing Provider. `/model switch` retains its project/workspace default scope.
- Local builds, the complete unit suite, critical user journeys and Bridge health regressions passed. Live Feishu delivery and paid model calls were not repeated for this release preparation.
- npm `beta` advances to this version. Stable channels continue serving v0.3.4.

Install with `npm install -g cc-connect-next@beta` or `cc-connect-next update beta`.
