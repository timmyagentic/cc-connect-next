# cc-connect-next v0.3.2-beta.1

## 中文

新增可选的飞书/Lark 未读完成通知提醒（#152）。Codex 和 Claude Code 共用 Engine 完成链路；默认关闭，按项目机器人和应用范围内的用户 ID 单独启用。Stable 和 npm latest 保持 v0.3.1。

- 成功回合的最终答复送达后，在原会话/话题发送一条新的短完成通知。默认等待一小时；`unread_reminder_delay_mins` 可配置为 1–10079 的整数分钟值，重启后应用于新通知，已有记录保留原到期时间。
- 仅向 `unread_reminder_users` 明确列出的回合发起人发送一次私聊提醒，附摘要和原会话入口；同一接收人的到期记录可聚合。已读、原话题继续发消息或撤回相关消息会取消提醒。
- 失败、取消、静默、未到终态和最终答复发送失败的回合不产生通知。查询故障按未知状态处理并有限退避，提醒不会调用模型或启动额外 Agent 回合。
- 修复慢查询耗尽整批发送时限的问题：查询最多 30 秒，随后独立保留最多 15 秒发送已确认未读的条目；未查完的后续记录留待下一轮，停止和取消仍会阻止发送。
- 按项目、机器人应用及平台域持久化有界队列；发送前持久标记尝试，避免重启后重复提醒。发送结果不确定或标记后崩溃可能漏提醒，不承诺必达。
- 同时包含官网视觉与内容更新（#151）。

```sh
npm install -g cc-connect-next@beta
cc-connect-next --version
```

也可使用 `cc-connect-next update beta`。配置与限制见 [未读提醒文档](https://github.com/timmyagentic/cc-connect-next/blob/v0.3.2-beta.1/docs/unread-reminders.md)。需要各机器人已有的消息读取、已读查询和私聊发送权限；发布不会自动启用功能或重启服务。

本地回归覆盖可配置默认值与边界、慢批次发送、重启恢复、取消和存储失败。真实飞书/Lark 收发、已读回执与会话入口端到端验收仍为 UNVERIFIED；已读状态不代表最终答复已被理解。

## English

Add opt-in Feishu/Lark unread completion reminders (#152) through the shared Engine completion path for Codex and Claude Code. Disabled by default; configure each project bot and its app-scoped recipient IDs separately. Stable and npm latest remain v0.3.1.

- Post a fresh short completion notice after a successful final answer is delivered. Wait one hour by default, configurable with integer `unread_reminder_delay_mins` from 1 to 10079. Restart applies the new delay to future notices; persisted deadlines stay unchanged.
- Send at most one private reminder with a summary and conversation link to explicitly listed turn initiators, with batching for the same recipient. Reading, continuing in the original topic, or recalling the relevant messages cancels pending reminders.
- Failed, canceled, silent, nonterminal and unsuccessfully delivered turns do not schedule notices. Query errors remain unknown with bounded backoff. Reminders do not invoke models or start Agent turns.
- Preserve a separate send budget after slow queries: up to 30 seconds for queries followed by up to 15 seconds for confirmed unread candidates. Defer unfinished later queries; cancellation and shutdown still prevent sends.
- Persist bounded queues per project, app and domain. Claim attempts durably before sending to prevent repeat reminders after restart; ambiguous sends or a crash after claiming may lose a reminder.
- Include the website visual and content refresh (#151).

Install with `npm install -g cc-connect-next@beta` or `cc-connect-next update beta`. See the unread-reminder documentation for setup and limitations. Existing bot read/read-receipt/private-message permissions are required. Publication does not enable the feature or restart services.

Local regression coverage includes delay defaults/bounds, slow batches, restart recovery, cancellation and storage failures. Real Feishu/Lark delivery, read receipts and conversation links remain UNVERIFIED end to end. A read receipt does not prove that the final answer was understood.
