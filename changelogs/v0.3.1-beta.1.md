# cc-connect-next v0.3.1-beta.1

## 中文

这是 v0.3.0 之后首个 v0.3.1 Beta，汇总 main 已合并的会话速度切换、飞书上下文与
反馈可靠性改进，并包含 Codex 连接断开与终态事件修复。Beta 供主动选择的用户试用，
Stable 仍为 v0.3.0。

### 主要变化

- **Codex 回合可靠结束。** 活动回合遇到 EOF 或读取失败会及时报错结束，
  队列满时保留完成与错误事件，避免继续等待空闲超时。迟到的启动响应不会
  重新激活已结束回合；正常完成、空闲及主动关闭不会重复报错。
- **会话内切换速度。** `/speed` 查看当前选择，`/speed fast`、`/speed default`
  将支持的档位保存到当前会话，从后续回合生效，无需重启。保留模型、推理强度、
  历史和正在执行的回合；不支持或无法核验的档位会明确提示。
- **被提及时补充群聊上下文。** 飞书/Lark 可按配置在明确提及时补读有限的近期
  讨论，区分群聊与话题，附带发言者、时间和回复关系。成功消费的上下文不会
  重复加入；未提及的消息保持静默，不新增轮询或扩大读取权限。
- **群聊与话题默认归属更明确。** 普通群聊默认共享会话，真实话题默认独立。
  现有历史保留但不会自动合并；普通私聊默认键不变，显式关闭共享或话题隔离
  的配置仍受支持。
- **长任务反馈保留原始请求。** Foundation v0.1.3 会冻结有界、脱敏的回合诊断，
  在长任务、后端故障及宿主重启后保留请求来源，并持久化报告 ID 与 Relay 回执。
  已批准的同一报告会合并，重试不盲目重复创建 Issue，现有命令、卡片和确认方式不变。
- **登录与额度错误更好恢复。** Codex 登录刷新失败会给出本地化恢复指引，
  认证阻止恢复时保留已保存会话；认证及额度不足不再自动弹出缺陷反馈建议，
  手动反馈仍可使用，标题优先采用最新错误摘要。
- **更新验证更可靠。** `--version` 不再初始化 daemon 日志或后台更新检查。
  npm 已安装成功但版本校验失败会明确报告，并保留运行中的服务，不自动重启。

### 升级与兼容性

```bash
npm install -g cc-connect-next@beta
cc-connect-next --version
```

独立安装可使用 `cc-connect-next update beta`，聊天可使用 `/upgrade beta`。
持续选择 Beta 可设置 `update_channel = "beta"`；省略该配置仍使用 Stable。
本次仅发布 GitHub prerelease 与 npm `beta`，不会将 `latest` 改为 Beta。

- 新客户端使用 `/v2/feedback`。Relay 运维方必须先部署同时兼容 v1/v2 的服务及
  `FEEDBACK_REPORTS` SQLite 迁移。现有 `/v1/feedback` 配置会映射到同源 v2 路径，
  协议拒绝后不会降级重发；自托管 Relay 也需要先完成该升级。
- 群聊未显式配置共享和话题隔离时，将采用新的默认值。旧会话历史保留，
  不会自动搬入新的共享或话题会话；需要原行为时请显式配置。
- 仅安装新 CLI 不会替换仍在运行的旧 daemon，需在合适时机单独加载新版本。
- 原生 Windows 运行、真实消息平台故障复现仍为 UNVERIFIED。

## English

This first v0.3.1 Beta collects the session speed controls, Feishu context, and
feedback reliability work merged into main since v0.3.0, including Codex
transport termination and terminal-event fixes. It is opt-in; Stable remains v0.3.0.

### Highlights

- **Reliable Codex turn completion.** EOF or read failures promptly finish an
  active turn with an error. Full queues retain completion and error events
  instead of leaving the user waiting for an idle timeout. Late start responses
  cannot reactivate finished turns; normal completion, idle sessions, and
  intentional shutdown do not produce duplicate failures.
- **Per-session speed selection.** `/speed` shows the selection, while
  `/speed fast` and `/speed default` persist supported choices for subsequent
  turns without restarting. Model, effort, history, and the active turn keep
  their existing behavior. Unsupported or unverifiable tiers fail explicitly.
- **Recent group context on mentions.** Opt-in Feishu/Lark context reads add
  bounded recent discussion on explicit mentions, separating chats and topics
  and preserving sender, time, and reply attribution. Successfully consumed
  context is deduplicated. Unmentioned messages stay silent; no polling or
  broader permission is introduced.
- **Clearer default session ownership.** Ordinary groups share sessions by
  default, while real topics are isolated. Existing history is retained rather
  than merged. Ordinary private-chat defaults and explicit opt-outs remain.
- **Durable long-task feedback.** Foundation v0.1.3 freezes bounded, redacted
  turn diagnostics and preserves the initiating request across long tasks,
  backend failures, and host restart. Report IDs and Relay receipts survive
  restart; approved copies coalesce and retries avoid blind duplicate issue
  creation. Existing commands, cards, and confirmation steps remain.
- **Actionable authentication and quota errors.** Codex login refresh failures
  offer localized recovery guidance without discarding saved conversations.
  Authentication and quota failures no longer automatically offer bug reports;
  manual feedback remains, with titles based on fresh error summaries.
- **Safer update verification.** `--version` avoids daemon logging and background
  update checks. Completed npm installs with failed verification are reported
  explicitly while the running service stays alive without an automatic restart.

### Upgrade and compatibility

```bash
npm install -g cc-connect-next@beta
cc-connect-next --version
```

Standalone installations can use `cc-connect-next update beta`; chat can use
`/upgrade beta`. Set `update_channel = "beta"` to follow Beta explicitly.
Omitting it still selects Stable. This publication uses GitHub prerelease and
npm `beta`; it does not move `latest` to Beta.

- The new client uses `/v2/feedback`. Relay operators must deploy dual v1/v2
  support and the `FEEDBACK_REPORTS` SQLite migration first, including for
  self-hosted Relays. Existing `/v1/feedback` configuration maps to the same
  origin's v2 path; a rejection never triggers a downgraded retry.
- Omitted group-sharing and topic-isolation settings now use the new defaults.
  Existing session history is retained, not moved into new shared/topic
  sessions. Configure explicit opt-outs when the old behavior is required.
- Installing a CLI does not replace a running old daemon; load the new version
  separately at an appropriate time.
- Native Windows execution and real messaging-platform fault reproduction
  remain UNVERIFIED.
