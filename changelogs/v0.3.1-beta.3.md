# cc-connect-next v0.3.1-beta.3

## 中文

修复飞书图片、视频及附件输入可能静默遗漏的问题（#146），并让各 Agent 的附件落盘失败明确可见。Stable 和 npm latest 仍为 v0.3.0。

- 首次 Range 探测返回 206 但缺少 Content-Range 时，丢弃探测响应并回退一次普通 GET。其他无效范围和后续分块仍严格拒绝；保留认证、大小上限、总超时、有限重试、API 错误信封检查及取消语义。
- 提取当前富文本内嵌视频的 FileKey，同时交付完整视频文件及可用封面；独立视频也交付文件。修正文件 MIME 检测和缺省视频扩展名，并校验图片内容类型。
- 图片、视频、文件下载失败、缺少附件元数据或不支持的文件夹产生明确提示；取消后不再派发媒体输入。混合消息保留可用附件及失败提示。
- Agent 附件落盘失败时停止该次不完整输入；不支持图片的 Agent 明确报错。同名附件按来源消息隔离。Claude 的内联图片输入在可选磁盘副本失败时仍可用。
- 不扩大群历史附件下载。引用文件仍要求显式 @机器人及当前用户为原上传者，并保留引用下载失败反馈。

### 验证范围

回归测试覆盖首次探测兼容、后续范围一致性、MIME、错误信封、取消、部分及纯媒体失败、同名落盘和各 Agent 的失败处理。专用飞书 QA 群的机器人合成样例验证了真实混合帖解析、图片及视频下载、PDF/TXT/音频字节一致性与同名文件隔离；一次真实 Codex 调用正确读取图片编号、TXT/PDF 值及视频文件大小。

机器人样例组件测试不等同于真人入站全链路验收。真人入站、本人引用成功/拒绝边界及语音转写尚未完成真实端到端验证；这些边界的本地回归测试与真实验收分开记录。视频文件或封面可用不代表模型理解整段视频。现场未复现缺少 Content-Range 的异常响应，该分支由本地回归覆盖。

```bash
npm install -g cc-connect-next@beta
cc-connect-next --version
```

也可使用 `cc-connect-next update beta`。没有新的必填配置或新增飞书权限要求；发布本身不会重启现有服务。

## English

Fix silent omissions of Feishu images, videos and attachments (#146), and surface attachment staging failures across Agent adapters. Stable and npm latest remain v0.3.0.

- Retry with one plain GET only when the initial Range probe returns 206 without Content-Range. Discard that probe body; retain strict validation for other invalid ranges and subsequent chunks, authentication, size limits, overall timeout, bounded retries, API error envelopes and cancellation.
- Extract embedded video FileKeys from current posts and deliver the full video plus its available cover. Standalone videos also deliver their file. Correct MIME detection, default video extensions and image content validation.
- Report failed media downloads, missing attachment metadata and unsupported folders. Keep usable items and failure notices in mixed messages, and avoid dispatch after cancellation.
- Reject incomplete Agent input when attachment staging fails; explicitly report unsupported image input. Isolate same-name files by source message. Claude inline images remain usable when only an optional disk copy fails.
- Preserve historical attachment boundaries: quoted files still require an explicit bot mention and the triggering user to be the original uploader. Surface allowed quoted-file download failures.

Regression coverage includes probe compatibility, chunk consistency, MIME, envelopes, cancellation, partial/pure-media failures, file isolation and Agent staging failures. Bot-generated synthetic fixtures in a dedicated Feishu QA group exercised real post parsing, resource downloads, byte-identical video/PDF/TXT/audio and isolated staging. One real Codex call read image numbers, TXT/PDF values and video file size.

These component checks are not human-inbound end-to-end acceptance. Real human inbound, own-upload quote acceptance/rejection and speech transcription remain unverified end to end. Video file/cover availability does not imply understanding the entire video. The missing-Content-Range condition did not occur live and is covered by local regression tests.

Install with `npm install -g cc-connect-next@beta` or `cc-connect-next update beta`. No new required configuration or broader Feishu permissions. Publication does not restart running services.
