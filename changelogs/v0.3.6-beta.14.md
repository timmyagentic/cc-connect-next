# cc-connect-next v0.3.6-beta.14

## 中文

- 支持为 prompt Cron 任务独立配置 `service_tier`，通过 CLI 创建、编辑、API 与 JSON 持久化，并在该次任务执行时应用。空值恢复继承，普通聊天的速度设置不变；Shell 任务不支持此字段。详见 [PR #238](https://github.com/timmyagentic/cc-connect-next/pull/238)。
- 速度值使用当前模型目录的真实 tier ID，不把显示名 Fast 当作固定 ID；例如某些目录中的 Fast 对应 `priority`。模型、推理强度和速度可独立设置，排队任务保留本次选择。
- 在线项目提供 Agent 级目录时，在创建与编辑阶段按有效模型预检；仅由具体会话提供的目录留到执行时校验；补齐管理 API 字段传递与编辑归一化，并确保仅设置任务速度后也会恢复普通回合默认值。
- 验证边界：本次验证覆盖本地回归与发布 CI、安装包及 npm 安装；未执行真实上游付费 fast Cron 任务，未验收实际响应速度或费用。
- 安装：`npm install -g cc-connect-next@beta`。稳定渠道保持 v0.3.5。

## English

- Add an optional per-task `service_tier` for prompt Cron jobs, supported by CLI creation/editing, the API, and JSON persistence. Apply it only to that task turn; an empty value restores inheritance without changing ordinary-chat speed settings. Shell jobs do not support this field. See [PR #238](https://github.com/timmyagentic/cc-connect-next/pull/238).
- Use the active model catalog's actual tier ID rather than treating the display name Fast as a fixed ID; some catalogs map Fast to `priority`. Model, reasoning effort, and speed are independently configurable, and queued tasks preserve their choice.
- Preflight the effective model when creating or editing an online project that exposes an Agent-level catalog; session-only catalogs are validated at execution. Preserve the field through the management API, normalize edits, and explicitly restore ordinary-turn defaults after a speed-only task override.
- Verification boundaries: local regressions, release CI, public artifacts, and npm installation are covered. No live paid upstream fast Cron job was executed, and actual latency or billing was not evaluated.
- Install with `npm install -g cc-connect-next@beta`. Stable remains v0.3.5.
