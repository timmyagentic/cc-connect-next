# cc-connect-next v0.3.6

## 中文

将 v0.3.6-beta.14 提升为稳定版；本次仅更新发布元数据和说明，不新增运行时代码。相对 v0.3.5：

- **飞书上下文与中途补充**：普通历史截断保持静默，但查询失败或已选内容、附件未读全仍提醒。历史附件支持最多 12 个资源、100 MiB 与共享 45 秒时限；启用群聊补读时保留显式引用和话题原帖。普通补充沿用当前回合参数，在支持的后端并入执行，避免排队任务丢失及卡片回复身份错位。
- **卡片与 Hook**：绑定用户的表单卡片返回文本与 HMAC 回执，保留 Card 2.0 结构。命名 `card.action` Hook 支持本地命令或 HTTP 处理器，普通按钮可通过 `hook_action` 指定动作。新增仅携带路由元数据的 `message.observed` 和 `reply.completed` 事件；不承诺持久投递或失败重投，处理器须自行保证幂等。
- **定时任务**：Cron / Timer SQLite 历史通过 `[history] enabled = true` 显式开启，默认关闭，配置修改后需重启。Prompt Cron 可独立指定 `service_tier`，使用模型目录中的真实 tier ID（例如 `priority`），任务结束后恢复普通聊天默认值；Shell 任务不支持此项。实际速度与费用由服务方决定。
- **恢复能力**：普通聊天重启恢复限定为本地 Codex app-server、飞书 rich Card 2.0 和持久会话存储组合。已完成回合只补交付，中断回合沿原会话续跑。明确的加密上下文校验失败会先备份原始历史，再在同一会话中静默重试一次，不创建替代线程。备份失败、历史不完整、身份不匹配或无法核对的活动命令等情况停止恢复。密文独有上下文不参与重试；保留工具记录不保证模型后续绝不重复操作。详见 [beta.13 的恢复边界](https://github.com/timmyagentic/cc-connect-next/releases/tag/v0.3.6-beta.13)。
- **安装与展示**：修复 npm 下载重定向后安装进程不退出的问题；网站首页增加协作演示并适配宽屏和手机方向。

### 更新及验证边界

- 稳定版安装或更新：`npm install -g cc-connect-next@latest`。已有 daemon 应在当前任务完成后重启，并在实际使用的平台发送一条消息验收。
- 升级或降级前备份配置、会话状态及可选历史数据库；旧版不支持新配置、Hook 和恢复能力。不会因升级自动开启 SQLite 历史。
- 发布流水线负责完整自动化测试、签名与六平台产物校验、公开下载及 npm 注册表检查。模拟 Agent / 平台测试不等同于真实端到端验收；本次未执行真实飞书回调、上游签名错误、运行中 daemon 升级或付费 fast Cron 任务。

## English

Promote v0.3.6-beta.14 to stable. This release changes metadata and notes only, not runtime code. Since v0.3.5:

- **Feishu context and steering:** keep routine history truncation quiet while reporting failed queries and unread selected content or attachments. Bound history attachments to 12 resources, 100 MiB and a shared 45-second deadline. Preserve explicit references and topic roots with group catch-up. Ordinary follow-ups inherit the active turn's parameters on supported backends, without dropping queued work or restoring stale card sender identities.
- **Cards and hooks:** owner-bound form cards return text and HMAC receipts while preserving Card 2.0. Named `card.action` hooks support local commands or HTTP handlers; ordinary buttons can specify `hook_action`. New `message.observed` and `reply.completed` events carry routing metadata only. Delivery is not durable and has no guaranteed retry; handlers must be idempotent.
- **Scheduled tasks:** Cron / Timer SQLite history is opt-in via `[history] enabled = true`, disabled by default, with a restart required after configuration changes. Prompt Cron jobs can select `service_tier` using the model catalog's real tier ID (for example, `priority`) without changing ordinary-chat defaults. Shell jobs do not support it; actual speed and billing depend on the provider.
- **Recovery:** ordinary-chat restart recovery is scoped to local Codex app-server, Feishu rich Card 2.0 and persistent session storage. Completed turns redeliver the recorded answer; interrupted turns continue in the original thread. An explicit encrypted-context validation failure backs up original history and silently retries once in that same thread, with no replacement thread. Backup failure, incomplete history, identity mismatch or unreconciled active commands stop recovery. Encrypted-only context is unavailable to the retry; retained tool receipts cannot guarantee no repeated model action. See [beta.13 recovery boundaries](https://github.com/timmyagentic/cc-connect-next/releases/tag/v0.3.6-beta.13).
- **Installation and presentation:** fix npm installer processes remaining alive after download redirects, and improve the website's collaboration demo and responsive layout.

### Upgrade and verification boundaries

- Install or update with `npm install -g cc-connect-next@latest`. Restart an existing daemon after active work completes, then verify a real message on your platform.
- Back up configuration, session state and any optional history database before upgrading or downgrading. Older versions do not support the new settings, hooks or recovery features. Upgrading does not enable SQLite history automatically.
- The release pipeline performs full automated checks, signing and six-platform artifact validation, public-download verification and npm registry checks. Simulated Agent / platform tests are not live end-to-end acceptance. Live Feishu callbacks, upstream signature faults, running daemon upgrades and paid fast Cron tasks were not exercised for this release.
