# cc-connect-next v0.3.5-beta.12

## 中文

- 聊天模型和推理强度统一保存在对应项目的 `[[projects.chat_models]]` 中；`/model` 与 `/reasoning chat` 可以分别设置和重置，`/config reload` 会应用配置中的新增、修改和删除。
- 启动时迁移旧的聊天模型和推理强度绑定；显式 TOML 设置优先，先保存配置再清理旧状态。模型与推理强度的 Agent/Provider 身份冲突时会报错并保留源数据，不会静默切换。其他项目状态保留。
- 降级前请备份配置和状态：旧版本可能不读取新位置中的推理强度，迁移也无法恢复此前已删除的数据。
- 对未分类的 Agent 上游错误，卡片及普通消息回退展示按现有规则脱敏的错误详情，同时保留已显示的部分回答；这些诊断不会加入助手历史。
- 自动化验证覆盖迁移失败与重试、独立重置、重载、并发保存、上游错误卡片与回退。真实飞书交互和付费模型请求未执行。
- Beta 安装：`npm install -g cc-connect-next@beta`。稳定渠道保持 v0.3.4。

## English

- Persist chat model and reasoning effort together in each project's `[[projects.chat_models]]`. `/model` and `/reasoning chat` can be set and reset independently; `/config reload` applies additions, edits, and removals.
- Migrate legacy chat model and reasoning bindings at startup. Explicit TOML values win, and configuration is saved before legacy state is cleared. Conflicting Agent/Provider identities stop migration and retain the source data; unrelated project state is preserved.
- Back up configuration and state before downgrading: older versions may not read reasoning effort from its new location, and migration cannot restore previously deleted data.
- Display upstream Agent error details redacted by the existing rules in cards and text fallback while retaining any already-visible partial answer. Diagnostics are not added to assistant history.
- Automated checks cover migration failures and retries, independent resets, reloads, concurrent saves, and upstream error cards and fallback. Live Feishu interactions and paid model requests were not exercised.
- Install the beta with `npm install -g cc-connect-next@beta`. Stable channels remain on v0.3.4.
